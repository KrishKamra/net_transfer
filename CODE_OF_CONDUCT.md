# Code of Conduct

This project is coursework. The people working in it are classmates, reviewers, and course staff. The standard below applies to issues, reviews, lab sessions, and any other space set up for this repository.

## Expected

- Critique the change, the protocol, and the code. Leave the person out of it.
- Read the diff before you approve it. If a transfer, a reply code, or a sandbox check is wrong, say so plainly and point at the file.
- Give someone room to answer. A short question beats a rewrite of their branch.
- Assume good faith when a result is confusing. Ask what they ran and which port answered.
- Credit work you did not do. Course submissions should say who wrote which part when the course asks for that.

## Not acceptable

- Insults, slurs, or jokes at someone's expense.
- Harassment, sexual attention, or sharing someone's private contact details.
- Publishing another student's credentials, password hashes, or unreleased coursework as if it were yours.
- Dismissing a reported bug without looking at it, or hiding a broken sandbox check because the happy path still works.

## Reporting

If something in this repository crosses the line above, contact the course staff who run the lab. If the repository has private maintainer contacts, use those. Do not file a public issue for a personal report.

Course staff decide what happens next. That can include an edit, a reverted change, or a report through the university's own process. This file does not replace that process.

## Scope

This conduct applies while you are acting in this repository. It does not police unrelated personal spaces. It does apply when you are representing this project in a lab, a review, or a course submission.
